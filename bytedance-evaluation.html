01 / 拆分评测职责

问题：一个 Judge 同时生成标准、核对事实、评价回答，很容易把“说得流畅”误判成“任务做对”。

我的重点：拆分评测职责，校准人机偏好，保留错误证据，让结果既能辅助版本选择，也能指导下一轮改动。

模块 输入与输出 设计目的
Rubric Agent 从 Query、历史与可信上下文生成原子标准 不看候选回答，避免贴着答案制定标准。
Fact Checker 对事实点查证，保留证据与未知结论 不让主 Judge 仅凭自身知识猜事实。
Judge 按冻结标准比较 A / B 回答并说明理由 限制职责，保留可追踪的打分依据。
Aggregator 汇总 AB / BA、人工标签和版本指标 区分稳定结论、低置信结果与需人工复核的样本。

02 / 评价标准也需要校验

一条可用的 Rubric 应只判断一个问题，并能对应到任务约束、可信证据或可观察行为。像“准确、完整、清晰”这样的笼统描述，需要继续拆解。

  1. 提取条件预算、时间、地点、格式，以及必须与禁止事项。
  2. 原子化与校验去掉重复、冲突与模糊判据，检查核心约束是否遗漏。
  3. 冻结后评分固定标准再评价候选回答，保留 Pass / Partial / Fail / Unknown 的边界。

为什么改变 Rubric 的筛选依据

阶段 当时的问题 调整方向
评分方差 拉开分差不代表符合人工判断，也可能出现所有模型都满分。 检查区分度，但不把方差当作唯一目标。
模型档位顺序 假设更强模型一定得到更高分，遇到具体业务可能倒挂。 不再把模型档位当作真实答案。
人工偏好锚点 需要同时判断方向、分差与稳定性。 以人评为参照，结合 MAE、Kappa、方向命中和 Swap 一致性选优。

03 / 三类主要问题

位置偏见：交换答案后，结论是否仍然成立

将回答匿名化，分别运行 AB 与 BA，再把结果映射回原始回答。发生反转的样本标记为低置信，而不是直接平均成一个看似确定的分数。

AB / BA 规则演示

AB 顺序选择回答 A；BA 顺序仍选择回答 A → 映射后结论一致，可进入汇总。

事实幻觉：把判断绑定到证据

区分“回答有没有忠实使用已有工具结果”和“工具结果本身是否可靠”。可核查事实保留证据；证据不足允许 Unknown，避免强行给出正确或错误结论。

打分漂移：记录评测配置，小步回归

对比 Prompt 版本时，同时观察方向准确率、MAE、±1 Accuracy、Swap 一致性和 False Tie。通过历史样本回跑，判断变化是修复了问题，还是改变了尺度。

现象 应检查的信号 处理边界
AB / BA 结论相反 Swap 一致性、方向反转 双向评测用于检测偏差，不能保证完全消除偏差。
Judge 断言事实正确但缺证据 关键错误检出、证据支撑情况 Fact Checker 也会漏检，不能直接当作绝对真值。
明显有优劣却被判平 False Tie 与人工非平样本 缩窄平局区间后仍需检查是否制造了虚假差异。

04 / 从 Bad Case 反推规则

案例一：中英夹杂规则误伤合理答案

现象：把出现英文视作硬性否决，会误伤技术术语、产品名和常见缩写。
调整：将语言风格问题与事实、任务完成度分开，改为限定范围的软惩罚。
沉淀：规则不仅要说明“什么不对”，还需要说明严重程度和影响维度。

案例二：平局规则抹平真实差异

现象：某版 Prompt 的 Tie Zone 过宽，将原本有胜负的 Case 压成平局。
调整：缩窄阈值，回跑人工非平样本，同时观察方向命中与 False Tie。
沉淀：减少随机波动不能以丢失区分度为代价。

案例三：“少说少错”的评测漏洞 问题观察 / 后续方案

复杂研究型回答包含更多事实点，如果只累计错误，却不评价任务覆盖，简短空泛的回答反而容易获得高分。

后续评测维度 要回答的问题
事实精度 可验证的事实中，有多少被可靠证据支持？
任务覆盖 用户明确要求的子问题，哪些被充分回答？
严重错误门禁 是否存在影响核心结论或关键操作的错误？
长短对照样本 在内容质量相近时，长度是否不恰当地影响偏好？

后续方案是联合判断事实精度与任务覆盖，并保留多维标签，支持算法侧的数据筛选与训练方案选择。

05 / 让评测稳定运行

批量评测中的工程错误会污染结论。例如解析失败被静默记成 0 分，看起来就像模型能力下降。因此，运行可靠性也是评测质量的一部分。

  1. 并发与限流使用 asyncio 与 Semaphore 控制请求并发，关注 QPM 与超时。
  2. 单条异常隔离区分请求失败、JSON 解析失败与真实业务低分；异常显式落盘。
  3. 增量与恢复使用 case_id、JSONL / Excel 改进结果，增量刷盘并支持断点续跑。

工程事故复盘：单条失败拖垮整个批次

在批量任务评审中，发现单条异常可能导致整批调用失败、未落盘结果丢失。改进重点包括任务级异常捕获、批量结果隔离、每 10 条增量刷盘，以及根据已完成 case_id 恢复运行。

评测改进结果

评测范围 改进结果 应用场景
真实线上回流 Case 机评与人评一致率 60% → 85%；版本评测一周 → 一天 业务评测与版本迭代
离线偏好评测 约 60% → 82% 离线偏好对齐
50 条验证集的版本比较 方向准确率 +6 个百分点，±1 准确率 +8 个百分点，MAE -0.08 Prompt 版本验证

06 / 后续方法探索

后续探索包括隐藏 Anchor、Judge 校准、多模型复核、GEPA 式候选 Prompt 优化和教育 VLM 分层评测。

  • 数据隔离：区分调试集、验证集与隐藏验收集，避免在同一批 Bad Case 上修改和报喜。
  • 理由校验：除判断方向外，检查 Judge 是否识别了真正影响人工偏好的约束与事实。
  • 候选优化：根据失败轨迹提出 Prompt 修改，经过独立回归后再决定是否采用。
  • 多模态迁移：将“看图、条件提取、推理、验证”分层归因，避免只用最终答案判断图像理解能力。
